## 2. Objetivos do design

- Manter o padrão visual e narrativo das aulas 07-10 (Reveal.js, blocos de 20-30min, hands-on real, prints reais do CI verde).
- Cada aula tem hook de abertura ligado à dor exposta pela aula anterior.
- Três das quatro aulas (11, 12, 13) adicionam um PR concreto ao demo `inteli-px4-cicd-demo`. A aula 14 não cria PR — usa PRs existentes (#5, #6 de alunos) e material curado.
- ADRs versionados para todas as decisões não-triviais (provider Multipass, multi-window SLO, etc.).
- Testes onde aplicável: code do PR demo precisa ter testes próprios; o material das aulas (HTML) é validado por inspeção visual e renderização Reveal.js.

## 3. Arco narrativo

Encadeamento linear ("cada aula resolve dor da anterior"):

| Transição | Dor exposta | Resolução |
|-----------|-------------|-----------|
| A10 → A11 | Pipeline correto mas lento (mission-test 8min) | Profiling do CI + cache + paralelização SITL |
| A11 → A12 | Runner é pet manual, ninguém sabe replicar | Terraform + Multipass provisiona runner como gado |
| A12 → A13 | Infra reprodutível, mas como saber se está bom? | SLO/SLI + error budget sobre métricas que A08 já extrai |

**Hook de abertura idêntico em cada aula:** começa com um print da aula anterior + 1 frase mostrando a dor concreta. **Hook de fechamento:** 1 frase do que vai abrir a próxima.

## 5. Aula 12 — Terraform local com Multipass

**Título proposto:** "Do pet ao gado: provisionando o runner com Terraform + Multipass"
**Prof:** José Romualdo · **Data:** 11/06 qui · **Duração:** ~2h20

### 5.1 Decisão de provider

VM local via **Multipass** (provider `larstobi/multipass`). Razões:

- Cross-platform real (Mac/Win/Linux).
- VM Ubuntu real, não container (preserva a lição "IaC para infra de verdade").
- Native virt (hvf no Mac, HyperV no Win, KVM no Linux) — leve.
- Custo zero, sem credenciais cloud, hands-on em qualquer laptop.

Alternativas consideradas e rejeitadas: Azure VM (custo, complexidade), libvirt (só Linux), VirtualBox (provider comunitário inconsistente), Docker (não é VM).

### 5.2 Blocos

| # | Tempo | Bloco | Conteúdo |
|---|-------|-------|----------|
| 0 | 5min | Hook + agenda | Print do setup manual do runner (bash script) de antes de A07. "Ninguém aqui sabe subir do zero. Mudou hoje." |
| 1 | 25min | IaC: declarativo vs imperativo | State, plan, drift. Comparação com Ansible/scripts. |
| 2 | 30min | Anatomia de um módulo Terraform | `providers.tf`, `main.tf`, `variables.tf`, `outputs.tf`, `versions.tf`. Onde mora o state. |
| 3 | 30min | Plan → Apply ao vivo | Walkthrough: `terraform init`, `plan`, `apply` provisiona VM Multipass + registra runner. Runner aparece verde no GH. |
| 4 | 25min | Hands-on | Aluno instala Multipass, clona PR #8, roda `plan`, `apply`, vê runner registrado, `destroy` no final. |
| 5 | 15min | Quiz + checklist + auto-estudo A13 | Gancho: "infra reprodutível. Mas como saber se mission-test está saudável? SLO." |

### 5.3 PR demo target

**PR #8 — "Runner como gado: Terraform + Multipass"** no `inteli-px4-cicd-demo`.

Conteúdo:
- `infra/terraform/runner-local/`:
  - `versions.tf` — providers `larstobi/multipass` (~1.x), `integrations/github` (~6.x)
  - `main.tf` — `multipass_instance` (CPU 2, RAM 2G, disk 10G), cloud-init para runner setup
  - `variables.tf` — vm_name, cpus, memory, disk, gh_org, gh_repo, runner_labels
  - `outputs.tf` — VM ipv4, runner registration status
  - `cloud-init/runner-setup.yaml` — instala actions-runner, registra com token, inicia serviço
- `.github/workflows/runner-iac-ci.yml` — em PR contra `infra/terraform/**`: `terraform fmt -check`, `validate`, `plan` (sem apply); comenta plan no PR
- `infra/terraform/README.md` — install Multipass (brew/snap/choco), passo-a-passo, troubleshooting, "como adaptar para cloud no exercício extra"
- `ADR-009-terraform-multipass-local.md` — por que Multipass e não outras opções, escopo "local-only para teaching", fallback Docker documentado

### 5.4 Prints reais esperados

Em `aulas/assets/img/aula12/`:

- `01-terraform-plan.png` — saída de `plan` mostrando recursos a criar

## 6. Aula 13 — SRE: SLO + error budget

**Título proposto:** "SLOs sobre o que você já mede: do pass/fail pontual ao orçamento de falhas"
**Prof:** Hermano · **Data:** 16/06 ter · **Duração:** ~2h20

### 6.1 Blocos

| # | Tempo | Bloco | Conteúdo |
|---|-------|-------|----------|
| 0 | 5min | Hook + agenda | Print "5/5 gates passed" do PR #4. "Isso te diz a taxa de falha das últimas 30 missions? Quanto tempo até recuperar?" |
| 1 | 25min | SLI · SLO · Error Budget | Hierarquia: SLI mede, SLO declara meta, budget mostra "quanto podemos quebrar". Pontual vs sustentado. |
| 2 | 30min | Escolhendo SLIs | Discussão dirigida: success rate first-try, p95 duration, rollback time. Janela (7/30 dias), "good event" / "valid event". Percentil > média. |
| 3 | 30min | Walkthrough PR #9 | `slos.yaml`, `tools/error_budget.py`, job CI `slo-check`, comentário no PR com burn %, badge no README. |
| 4 | 25min | Hands-on | Aluno injeta falha proposital, vê budget queimando 3% por miss. Debate: ajustar SLO ou ajustar código? |
| 5 | 15min | Quiz + checklist + auto-estudo A14 | Gancho: "tudo medido e controlado. Gargalo agora é humano — IA acelera trabalho técnico crítico sem virar muleta?" |

### 6.2 PR demo target

**PR #9 — "SLO/SLI + error budget"** no `inteli-px4-cicd-demo`.

Conteúdo:
- `slos.yaml` — 3 SLOs declarativos (success rate, p95 duration, rollback time) com janelas multi (1h/24h/7d/30d)
- `tools/error_budget.py` — parser YAML, reads `metrics/history.jsonl`, calcula burn rate por janela
- `metrics/history.jsonl` — append-only de cada mission run (timestamp, run_id, success, duration_s, rollback_s)
- `.github/workflows/ci.yml` — novo job `slo-check` rodando após mission-test
- `.github/workflows/slo-comment.yml` — comentário no PR: tabela SLO, target, current, budget remaining
- `docs/sre-basics.md` — glossário (SLI/SLO/SLA/error budget), exemplos com PRs #1-#4
- `ADR-010-multi-window-slo.md` — por que janelas múltiplas (captura tanto regressão aguda quanto degradação lenta)

### 6.3 Prints reais esperados

Em `aulas/assets/img/aula13/`:

- `01-slos-yaml.png` — slos.yaml com 3 declarações
- `02-slo-burn-comment.png` — comentário "🟡 Budget burn: 12% (30d window)"

## 11. Não-objetivos

Fora do escopo destas 4 aulas:

- Cloud real (AWS/Azure/GCP) para o runner — mantém-se local com Multipass; cloud fica em exercício extra.
- Observabilidade externa (Grafana, Prometheus, Loki) — `history.jsonl` é suficiente didaticamente.
- DevSecOps (SAST/DAST avançado, supply chain) — coberto em A06.
- Testes E2E em hardware real — depende de drone físico, fora da capacidade do módulo.
- Avaliações de IA generativa quanto à qualidade (não é foco em A14; foco é fluxo + revisão crítica).

1. Arquivo `aulas/aulaXX.html` renderiza limpo em Reveal.js (sem erros no console)
